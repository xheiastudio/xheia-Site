# Xheia Website — Implementation Spec

Source documents: `BRANDFINAL.md` (brand truth) and the structure plan at `/Users/hoda/.claude/plans/read-brandfinal-md-in-this-sparkling-starfish.md` (approved). This spec is the implementation-ready version of that plan — all open decisions from the interview are resolved below. Implement against this file in a fresh session; don't re-litigate decisions already made here.

## Stack

- **Framework:** Astro, static output (zero client JS by default; hydrate only the theme toggle, boot-sequence animation, and form as needed)
- **Hosting:** Netlify
- **Forms:** Netlify Forms (native — no third-party service)
- **Fonts:** IBM Plex Mono, IBM Plex Sans, and a pixel/bitmap display font (e.g. Press Start 2P)

**Revision note (reveal-animation bugfix + faster pacing):** the tagline/subhead/CTA's `.line-reveal` and the module "OK" badges' fade-in were built on a `steps(1)` "instant" animation trick (0.01s duration, jumps straight to the end value) with a computed floating-point `animation-delay` (e.g. `7.049999999999999s`). This had a real bug: `steps(1, jump-end)` only changes its rendered value at the *exact* end of its duration, and landing fractionally short of that exact instant — as floating-point-computed delays reliably do — left the Web Animations API reporting `playState: "finished"` while the element's computed opacity stayed at its 0%-keyframe value forever. In practice this meant the tagline never actually appeared on a fresh first visit (only `boot-skip`, which sets `opacity` directly via a CSS class rather than relying on the animation, ever showed it — which is why it looked like it "disappeared after the first load": it never genuinely appeared in the first place, and only a *second* visit's `boot-skip` path worked). Fixed by replacing the `steps(1)` snap with a real eased transition — `.line-reveal` now animates `opacity` + `translateY(0.6em → 0)` over 0.45s with a punchy `cubic-bezier(0.16, 1, 0.3, 1)` curve (smooth timing functions have no exact-boundary cliff — landing 0.0001% short of "done" is visually identical to done), and the module-status fade got the same fix with a short 0.15s `ease-out`. Separately, live feedback that the whole sequence "loads really slowly" — `CPS` 70→105, `DWELL` 0.1s→0.06s, `BEAT` 0.25s→0.15s, module progress-bar fill 0.35s→0.25s — cuts total sequence time from ~9s to ~6s.

## Design tokens

Enforce theme colors and type tiers as shared tokens, not per-component choices:

**Colors**
| Token | Hex | Notes |
|---|---|---|
| Ink | `#0D0D10` | Dark bg / light-mode text |
| Paper | `#F2F0EA` | Light bg / dark-mode text |
| Aperture blue | `#3E6BF0` | Primary accent, both modes |
| Signal green | `#3EF07C` | **Dark mode only** — never render in light mode |
| Flare coral | `#FF8A5C` | Secondary accent, sparing use, never simultaneous with green as primary |
| Mist | `#9A9A93` | Secondary text, captions |

Dark mode: Ink bg, Paper text, Signal green active (mark/status), Aperture blue + Coral available.
Light mode: Paper bg, Ink text, Aperture blue for links/CTAs, Coral for occasional emphasis, **no green**.

**Type tiers**
| Tier | Font | Scope |
|---|---|---|
| Display | Pixel/bitmap (Press Start 2P) | Boot-sequence screens elsewhere/social graphics, and (site-wide as of the big visual pass) section headings/numerals — short phrases/labels only, never body text. **Not used for Home's Hero headline** (single-terminal-frame pass — it's styled as terminal output in IBM Plex Mono instead) |
| Wordmark/UI/code | IBM Plex Mono | Logo, buttons, nav labels, terminal moments |
| Body | IBM Plex Sans | All paragraph copy — case studies, about, form labels |
