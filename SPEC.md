# Xheia Website — Implementation Spec

Source documents: `BRANDFINAL.md` (brand truth) and the structure plan at `/Users/hoda/.claude/plans/read-brandfinal-md-in-this-sparkling-starfish.md` (approved). This spec is the implementation-ready version of that plan — all open decisions from the interview are resolved below. Implement against this file in a fresh session; don't re-litigate decisions already made here.

## Stack

- **Framework:** Astro, static output (zero client JS by default; hydrate only the theme toggle, boot-sequence animation, and form as needed)
- **Hosting:** Netlify
- **Forms:** Netlify Forms (native — no third-party service)
- **Fonts:** IBM Plex Mono, IBM Plex Sans, and a pixel/bitmap display font (e.g. Press Start 2P)

Both were cut after seeing the live site — the case-study placeholders read as literal CV bullet points on a landing page, and a dedicated origin-story section overweighted the personal narrative for what's meant to read as a reputable company. `Capabilities` (what the work is, not specific past wins) replaces `ProofStrip` on home; the origin story now lives only on `/about`. The route was also renamed `/work` → `/track-record` to match the nav label.

**Revision note (identity & discoverability pass):** the site had zero personal name anywhere, which is a real trust/discoverability gap for a solo consultant growing an international client base (see `BRANDFINAL.md`'s "Personal identity vs. company brand" addendum). Fix stays scoped to where a prospect doing due diligence would actually look — Home/Header/Hero were unchanged at the time. `/about` now reads in first person with a headshot slot; the Footer carries a one-line personal credit plus a personal-LinkedIn link; page meta descriptions name the operator for search (meta-only, not visible page copy). Name and LinkedIn URLs are placeholders (`[Your Name]`, `href="#"`) until supplied — same convention as `ContactForm`'s temporary delivery address.

**Revision note (truth-over-theater pass):** all four Track Record case studies were fabricated or unverified — three invented outright, and the fourth (life sciences) written as generic placeholder copy never sourced from the user's real work. All four were deleted; `/track-record` now shows an honest in-progress message when the collection is empty, and will show an anonymization disclaimer ("client details are withheld by agreement...") above the grid once real, user-supplied entries exist — no fabricated content goes back in. `scripts/generate-case-studies.mjs` (a bulk fictional-placeholder generator) was deleted for the same reason; future entries are hand-authored from real details. Separately, all site copy (including `BRANDFINAL.md`'s tagline and "What I do") switched from "we" to "I" — this is a solo consultancy, and the copy shouldn't perform team scale. `IdentityHook` (a one-line "[name] — biomedical science background..." strip linking to `/about`) was added directly under Hero on Home so the homepage doesn't read anonymous, without turning Home into a full personal profile — see `BRANDFINAL.md`'s updated "Personal identity vs. company brand" addendum.

**Revision note (big visual pass):** the site read as "boring" outside Hero — every other section was a plain bordered box with the same subtle hover state. Extended the retro/pixel visual system site-wide: `PixelRivets` (shared corner-hardware component, extracted from what was hand-duplicated only in Hero) and `PixelIcon` (shared coordinate-array-to-SVG-rects icon component, same technique as `PixelMark`) are now used across Capabilities, PillarBlock, EngagementStructure, CaseStudyCard, the Track Record empty-state, and About's headshot frame. The sitewide pixel cursor (previously Hero-only) now lives on `<html>` in `BaseLayout.astro`. Section headings/numerals escalate from mono to the Display tier (Press Start 2P) throughout — see `BRANDFINAL.md`'s updated type-tier scope. Added Astro's native `<ClientRouter />` for page-to-page transitions with a custom CRT-flicker effect, a brief boot-flicker on every page load, and a `steps()`-timing scroll-reveal so sections materialize rather than fade. The literal boot-sequence device (typed terminal lines, chrome-buttons bar) stays Hero-exclusive — only the surrounding pixel-art system went site-wide. No sound was added. **Implementation note:** enabling `<ClientRouter />` required migrating the reveal-on-scroll script and `ThemeToggle`'s click handler to listen for the `astro:page-load` event instead of running once at top-level, since soft navigation swaps `<body>` content without a hard reload.

**Revision note (structural redesign — "boxes under boxes"):** the previous pass fixed the boredom problem by applying one visual pattern (bordered box + rivets + icon) to every section — which just produced a new kind of sameness. This pass is a genuine restructure, not more decoration: (1) **Home is now Hero-only** (Header, Hero, Footer) — Capabilities/PillarBlock/EngagementStructure moved to a new **`/approach`** page (added to nav between Track Record and About), and `ContactCTA`/`IdentityHook` were dropped from Home since Hero already carries its own CTA. `IdentityHook` was deleted entirely; its content is now one more line in Hero's boot sequence (`$ operator --info`) rather than a separate element sitting below the terminal. (2) **Hero's boot sequence is much richer** — a fast module-loading preamble (pixel progress bars for `cleansing.sys`/`warehousing.sys`/`agentic_ai.sys`, named after the actual Capabilities categories, not new claims) plays before the existing typed `$ whoami` exchange, then the operator-info line; Hero now fills most of the viewport since it's the entire home page. (3) **The sitewide pixel cursor is real, not CSS** — `PixelCursor` is a JS-tracked visible element (mousemove + `transform`), replacing the old `cursor:` property swap, which was too subtle to register as a feature; only activates on fine-pointer devices, native cursor only hidden via a JS-added class so a JS failure never leaves a dead cursor. (4) **The three relocated sections each get a distinct interaction** instead of repeating one card pattern: `Capabilities` is a boot-menu (native `<details>`/`<summary>`, pixel-arrow selector, description revealed only for the open item), `PillarBlock` is a diagnostic self-check (opening a principle plays a "verifying..." progress bar, then a checkmark and the body text land — ties the interaction to the pillar's own meaning), `EngagementStructure` is a level-path (three nodes connected by a dashed line, game level-select map style; falls back to a stacked list under 40rem, the path metaphor doesn't survive narrow viewports).

**Revision note (real-content pass):** `xheia-content-worksheet.md` supplied real facts, replacing several placeholders and one full narrative direction. (1) **Name resolved**: every `[Your Name]` placeholder (About, Footer, BaseLayout meta, Hero) now reads **Hoda** — first name only, no surname, no pronouns anywhere, by explicit choice. (2) **Origin story rewritten**: the biomedical-science framing is dropped entirely (confirmed by the operator as not fitting) in favor of the real hook — four-plus years contracting across the UK, moving across industries rather than one specialism. Retail and Education, previously named as sectors with no real detail behind them, are dropped from the narrative until there is some. `BRANDFINAL.md` §1 updated first, then About and Hero's operator-info line to match. (3) **Three real, anonymized case studies** replace the empty Track Record collection: a life-sciences post-acquisition customer-intelligence pipeline, a public-sector CRM migration (the client description was softened from the worksheet's "biggest supply chain company in the UK" to "a major UK supply chain organisation" — the superlative was identifying even without a name), and a fitness-sector compensation-modelling engagement. (4) **About stays service-first**: per an explicit decision, day-to-day project detail lives only in the Track Record case studies, not About — About tells the "who/why trust" story in three short paragraphs, not a CV. (5) **New `Tools` component** on `/approach`: the confirmed real tech stack (Azure Synapse, Power BI, Power Automate, SharePoint, HubSpot, Apollo, Python, SQL, Microsoft Foundry, rapidfuzz, Claude Code) as a small pixel-tag list, reusing `CaseStudyCard`'s existing tag style. (6) **Hero layout fix**: the boot log now sits in its own bordered sub-panel with a dashed divider before the brand-row/headline content, instead of floating loose against a much larger display-font headline — fixes the "boot log on top, then massive writing underneath" seam. LinkedIn/GitHub/business email/headshot remain placeholders — no real values supplied yet.

**Revision note (terminal rewrite + Track Record → Work rename):** two changes, driven by user feedback plus an attached proof-of-work research doc (`compass_artifact_wf-eddf1452-6636-5de7-95fb-a723fc6b4008_text_markdown.md`). (1) **`Track Record` renamed to `Work`** (route, nav label, page title) — the research specifically flags "Track Record" as priming a resume reading for a services buyer; the existing case-study structure (anonymized, outcome-led Problem/Approach/Outcome) already satisfied the research's core recommendation, so only the label/route changed. Also added: a **sectors-served strip** on the Work page, derived from each case study's `tags` array (sector is always the last tag by convention) rather than hardcoded — stays in sync automatically as entries are added; and a **headline-result paragraph** on `/about` citing the life-sciences case study's six-tab Power BI dashboard across three acquisitions, since About previously had zero concrete proof in it. Both additions restate facts already published in the life-sciences case study — no new claims. Explicitly not done (blocked, not deferred by choice): a public-proof link (no article/demo/repo exists yet to link) and a named/testimonial-backed case study (no client permission or testimonials exist yet). (2) **Hero's boot sequence now types out every line**, not just the `$ whoami` exchange — a `typeLine()` helper derives each line's duration from its own character count (~70 chars/sec) so the whole sequence reads as one real terminal session rather than a mix of instant fades and one typed exchange. The headline/subhead/CTA are now wrapped in `.reveal-content` and stay hidden until a beat after the terminal's final caret — they "pop up" as the sequence's own final output, addressing the ask that they read as something the terminal produced rather than static page content sitting under it.

**Revision note (single terminal frame + tagline as terminal output):** several fixes to Hero, the first two planned together and the rest added from live-use feedback during the same pass. (1) **"Terminal within a terminal" fixed**: the boot log was a second, separately bordered/tinted box nested inside the outer CRT bezel's own window chrome — two visually nested frames read as two nested terminals. It now sits directly on the bezel's screen as one frame, with the boot log inside a single left-aligned `.terminal-body` — no more separate boxed panel, no more dashed divider. (2) **The tagline now reads as the terminal's own output, not a separate pixel-font headline**: previously the `<h1>` switched to the pixel display font in its own section below the divider — a different visual register from the terminal text above it. It's now styled as the terminal's own biggest line of output, prefixed with the same `>` glyph every response line uses, in IBM Plex Mono; the subhead gets a `//` comment-glyph prefix, extending the same idea. No invented code syntax (no `console.log(...)`, no fake `return` statement) — grounded in the terminal's existing visual language. The pixel display font no longer appears anywhere on Home (see `BRANDFINAL.md`'s updated Type System table). Brand-row (mark+wordmark) was also dropped from inside Hero — `Header` already shows it on every page including Home. (3) **The bezel now fills the available viewport height/width** instead of capping at `--content-max-width` — live feedback was that the terminal read as small and oddly proportioned against the page; boot-line/headline/subhead font sizes were bumped up to match, and `.screen` centers `.terminal-body` vertically so the larger frame doesn't just leave empty space below a top-anchored block. Falls back to intrinsic content height under 40rem viewport width, where forced full-height stretching just produces a large empty gap. (4) **The boot log types out once and ends with the tagline as its own final output; the whole thing (log + tagline + CTA) then stays on screen together.** An intermediate version of this same pass made the log loop forever with the tagline permanently static and independent of it — live use showed that's not what was wanted. Reverted to a one-time sequence: headline/subhead/CTA are timed items on the same `clock` the boot log uses, revealed via `.line-reveal` (the operator-response line's existing block-reveal technique — it and the headline/subhead all wrap onto multiple lines, and the per-character `.typed` technique breaks on wrapped text, confirmed by an earlier bug). A `boot-skip` class (set once per session via `sessionStorage`, after the sequence first completes) skips straight to the fully "booted" end state on repeat visits to Home, so revisiting doesn't mean sitting through the whole sequence again with the tagline hidden meanwhile. (5) **`PixelCursor`'s solid backing plate was removed** — live feedback was that it read as an unwanted dark box trailing the cursor; no other pixel-art element on the site uses a backing plate either, so the cursor is now just the arrow pixels with no fill behind them.

**Revision note (home finalization pass):** closing out Home after several iterative rounds. (1) **Hero reverts to a content-sized frame** — the previous pass's full-viewport-height stretch left empty space below the (fixed-length) content; `.bezel` is back to a normal block capped at `--content-max-width`, no forced height. (2) **Subhead copy**: "...so any AI you build on top actually holds up" → "...so whatever you build on it actually holds up" — drops the AI-specific framing for a full-stack-data-professional one, still grounded in the same "What I do" pillars (cleansing, migration, warehousing, BI). (3) **Header nav link text bigger** (`0.875rem` → `1.0625rem`). (4) **`PixelMark` bigger everywhere it appears** (Header `40`→`56`, Footer `18`→`24`) **and its existing idle blink made more noticeable** — it already blinked (added in the big visual pass) but the original 6s cycle with a ~2%-of-cycle closed-eye window was too subtle to register at a glance, the same failure mode the old CSS-only pixel cursor had; now a 3s cycle with a wider closed-eye window. (5) **Light mode's status accent is now Flare coral, not a fallback to Aperture blue** — see `tokens.css`'s `[data-theme="light"]` block. `--accent-primary` (links, CTAs) was already Aperture blue in both modes; letting `--accent-status` (LED, progress bars, module "OK" text, caret, footer status dot) fall back to that same blue in light mode collapsed two distinct roles into one color, reading as flat "just white and blue." `BRANDFINAL.md`'s own light-mode guidance already calls for "Coral for occasional secondary emphasis" — this corrects an unimplemented gap in `tokens.css`, not a new design decision. No new colors were introduced anywhere in this pass.

## Nav

`Xheia (mark+wordmark)` — `Work` — `Approach` — `About` — `Contact` — theme toggle — one CTA button. No dropdowns, no secondary items.

**Single contact path:** every CTA button, site-wide, is the same component with the label **"Start a conversation"**, and every one of them points to `/contact`. No calendar link, no chat widget, no second form anywhere.

## Components

- **Header/Nav** — theme toggle + nav links + CTA button
- **ThemeToggle** — dark (default) / light; persists to `localStorage`; respects `prefers-color-scheme` on first load
- **PixelMark** — eye-sprite logo, two color states per theme (see Colors below). Idle blink (3s cycle, brief closed-eye window) so the mark reads as "alive," not static — see home-finalization revision note for the size/blink-rate tuning.
- **Hero** — a single terminal frame (no nested boxed panel, see single-terminal-frame revision note), sized to its content and capped at `--content-max-width` (not a forced full-viewport stretch — see home-finalization revision note). A one-time boot sequence (module-loading preamble with pixel progress bars, the `$ whoami` exchange, an `operator --info` line carrying the identity hook) ends with the tagline headline and one-line outcome-framed subhead as its own final output, styled as the terminal's biggest `>`/`//` lines (IBM Plex Mono, not the pixel display font), then the CTA — the whole session stays on screen together once it finishes. Single-line boot items type out character-by-character; the operator-response line, headline, and subhead all reveal as a plain delayed block instead (wrapped text and the character-typing width-clip technique are incompatible). A `boot-skip` class shows the fully "booted" end state instantly on repeat visits to Home within the same session. Home is Hero-only, see structural-redesign revision note. **The literal boot-sequence device (typed lines, chrome-buttons bar) is Hero-exclusive** — the surrounding pixel-art system (rivets, cursor, scanlines) is shared site-wide as of the big visual pass.
- **PixelRivets** — shared 4-corner "hardware" detail for bordered panels (extracted from Hero). Requires the parent to be `position: relative`.
- **PixelIcon** — shared coordinate-array-to-SVG-rects icon renderer (same technique as `PixelMark`). Used for small icons in Capabilities and the pixel-art sun/moon in `ThemeToggle`.
- **PixelCursor** — real, visible, JS-tracked pixel-art cursor (not a CSS `cursor:` swap) rendered once in `BaseLayout.astro`. Fine-pointer devices only; native cursor hidden only via a JS-added class. Added in the structural-redesign pass, replacing the old CSS-only approach — see revision note above. Just the arrow pixels, no solid backing plate (dropped in the single-terminal-frame pass — it read as an unwanted dark box trailing the cursor).
- **Capabilities** — "what I do," on `/approach` (moved off Home in the structural redesign). Grounded in `BRANDFINAL.md` §1 "What I do" — links to `/work`. Rendered as a boot-menu: three `<details>`/`<summary>` items (Cleansing & migration / Warehousing & BI / Agentic AI systems), pixel-arrow selector, description revealed only for the open item.
- **CaseStudyCard** — fields: client/sector (or anonymized descriptor), problem, approach, outcome, tags[]. Single variant (always full detail) — used only on `/work`. Populated with three real, anonymized entries as of the real-content pass (life sciences, public sector, fitness); more get added by hand, one at a time, only from real details the user supplies. No Retail/Education entries — no real detail given yet.
- **PillarBlock** — "principles," on `/approach` (moved off Home in the structural redesign). Renders the three pillars from `BRANDFINAL.md` §5 (Truth over theater / Clarity is engineered, not promised / Built to survive scrutiny), copy condensed from that section directly — do not invent new pillar language. Rendered as a diagnostic self-check: each principle starts collapsed, opening it plays a progress-bar "verify" animation before the checkmark and body text land.
- **EngagementStructure / EngagementPhase** — "how I work," on `/approach` (moved off Home in the structural redesign). Three phases, in order: **Discovery → Build → Handoff**, rendered as a level-path — nodes connected by a dashed line, falling back to a stacked list under 40rem.
- **Tools** — real tech stack, on `/approach`, added in the real-content pass. Grounded directly in `xheia-content-worksheet.md` — nothing invented. Reuses `CaseStudyCard`'s pixel-tag visual style.
- **ContactForm** — fields: name, email, company, message. Submits via Netlify Forms. Delivers to `hoda.97@live.com` **(temporary — replace with the business address before public launch)**. Plain-text `mailto:hoda.97@live.com` fallback rendered near the form, not styled as a competing CTA
- **CTAButton** — single shared visual treatment, label always "Start a conversation", always links to `/contact`
- **Footer** — wordmark, personal credit line ("Built and run by Hoda"), social links (GitHub, personal LinkedIn, and a placeholder Xheia-company-LinkedIn slot not linked live yet), terminal flavor line, status dot (per §4 social banner reference)

## Design tokens

Enforce theme colors and type tiers as shared tokens, not per-component choices:

**Colors**
| Token | Hex | Notes |
|---|---|---|
| Ink | `#0D0D10` | Dark bg / light-mode text |
| Paper | `#F2F0EA` | Light bg / dark-mode text |
| Aperture blue | `#3E6BF0` | Primary accent, both modes |
| Signal green | `#3EF07C` | **Dark mode only** — never render in light mode |
| Flare coral | `#FF8A5C` | Secondary accent, sparing use, never simultaneous with green as primary |
| Mist | `#9A9A93` | Secondary text, captions |

Dark mode: Ink bg, Paper text, Signal green active (mark/status), Aperture blue + Coral available.
Light mode: Paper bg, Ink text, Aperture blue for links/CTAs, Coral for occasional emphasis, **no green**.

**Type tiers**
| Tier | Font | Scope |
|---|---|---|
| Display | Pixel/bitmap (Press Start 2P) | Boot-sequence screens elsewhere/social graphics, and (site-wide as of the big visual pass) section headings/numerals — short phrases/labels only, never body text. **Not used for Home's Hero headline** (single-terminal-frame pass — it's styled as terminal output in IBM Plex Mono instead) |
| Wordmark/UI/code | IBM Plex Mono | Logo, buttons, nav labels, terminal moments |
| Body | IBM Plex Sans | All paragraph copy — case studies, about, form labels |
